A scale target connects a capacity pool to infrastructure that can change the supply behind its destinations.

Each target identifies one scalable resource, the replica counts Arklow may command, and the connection used to observe and change it.

## Replica commands

Arklow commands one replica count at a time. The target's configured minimum and maximum are permission bounds on those commands, not a range delegated to the provider.

| Mode | Arklow changes | Provider behavior |
|---|---|---|
| **Autoscaler** | Sets the provider's autoscaling bounds to the commanded count, with provider-specific scale-to-zero handling | The provider converges to that count through its autoscaler |
| **Direct resize** | Requests the commanded replica count directly | The provider resizes the resource to that count |

Admission control remains active while new capacity provisions. Work can wait during that interval and resume as the destination becomes ready.

## Metric binding

A pool holds one scale target per resource that serves its work. The binding tells each target which measurements are about its resource: a query from one of your [metric sources](/resources/metrics/index), and the tag value that identifies the resource in what the query returns.

```text
target: model-a   query: company.perf.models   matches: model_id=M1
target: model-b   query: company.perf.models   matches: model_id=M2
target: model-c   query: company.perf.models   matches: model_id=M3
```

Let's follow one action from arrival to the target that serves it:

1. An action tagged `{customer_id=C1, model_id=M1}` routes to a destination in this pool.
2. Its [metric policy](/resources/metrics/index) matches those tags to series tags by name, selecting `request_latency{customer_id=C1, model_id=M1}`.
3. The target matching `model_id=M1` watches that series.
4. When the work pushes that series into pressure, reflecting the actual part of that infrastructure, `model_id=M1` grows.

The `model_id` on the action reached the target through the series: the policy carried the value across on the shared name, and the target matched it. The `customer_id` traveled the same way but does a different job; it says whose work the series describes.

One resource serves many customers. Two actions, `{customer_id=C1, model_id=M2}` and `{customer_id=C2, model_id=M2}`, produce two series: `request_latency{customer_id=C1, model_id=M2}` and `request_latency{customer_id=C2, model_id=M2}`. Both carry `model_id=M2`, so both belong to target model-b, and pressure on either one grows it. A customer with a private resource has a different `model_id` on their series, and with it their own target.

## Pool ownership

Every scale target belongs to one capacity pool. The target should change capacity that serves the destinations in that pool.

For example, a pool containing destinations backed by one model deployment can own the target for that deployment. Destinations backed by unrelated deployments belong in separate pools with separate targets.

One pool can have several scale targets when separate components contribute capacity to the same work. A metric binding can identify the component represented by each target.

## Write control

While the scale-targets member of [Write Control](https://app.arklow.io/dashboard/settings?tab=organization) is off, adjustments are recorded and not written. While it is on, Arklow writes replica counts within the target's permission bounds.

## Attach a provider target

<Steps>
  <Step title="Open the credential">
    Create or open the credential that can read the provider account.
  </Step>
  <Step title="Enable the provider">
    Under **Scale target providers**, enable Baseten, Together AI, or Google Cloud managed instance groups.
  </Step>
  <Step title="Sync the inventory">
    Click **Sync now**, then open [**Scale Targets**](https://app.arklow.io/dashboard/scale-targets).
  </Step>
  <Step title="Choose the resource">
    Select the model, endpoint, or managed instance group under **Provider inventory** and click **Attach**.
  </Step>
  <Step title="Select capacity">
    Choose the destinations this target serves, or an existing pool. Choosing destinations creates a new pool for the target, with those destinations as its members.
  </Step>
  <Step title="Set permission bounds">
    Enter the lowest and highest replica counts Arklow may command.
  </Step>
  <Step title="Bind a metric if needed">
    Select a metric query. Add a tag projection when the query covers several scalable resources.
  </Step>
  <Step title="Attach">
    Attach the target, then review its observations and adjustment history.
  </Step>
</Steps>

The two HTTP scale target kinds cannot enumerate customer-implemented endpoints. Create those targets with **New manual target**.
