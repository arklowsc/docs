The **HTTP scale API (autoscaling)** target commands a concrete replica count through your platform's autoscaler. Arklow sets the autoscaler's minimum and maximum to that count.

This mode uses the shared [status endpoint and authentication contract](/resources/scale-targets/http/index).

## Write contract

Arklow sends:

```http
PATCH {endpoint}/scale/autoscaling
Content-Type: application/json
```

```json
{
  "min_replicas": 3,
  "max_replicas": 3
}
```

Both fields contain the same commanded count after Arklow clamps it to the target's permission bounds. The count can be `0` when your platform supports scale-to-zero.

Return a `2xx` response after your platform accepts the new bounds. The status endpoint can return `settled: false` while the autoscaler or underlying capacity converges.

## Add an HTTP autoscaling target

<Steps>
  <Step title="Prepare the API">
    Implement the shared status endpoint and the autoscaling write endpoint.
  </Step>
  <Step title="Open scale targets">
    Go to [**Scale Targets**](https://app.arklow.io/dashboard/scale-targets), click **New manual target**, and select **HTTP scale API (autoscaling)**.
  </Step>
  <Step title="Enter the endpoint">
    Provide the public HTTPS base URL of the scale API.
  </Step>
  <Step title="Select authentication">
    Choose the HTTP Auth Headers credential containing the headers your API expects.
  </Step>
  <Step title="Select capacity">
    Choose the destinations served by this platform, or an existing pool. Choosing destinations creates a new pool with those destinations as its members.
  </Step>
  <Step title="Set permission bounds">
    Enter the lowest and highest replica counts Arklow may command. The minimum can be `0`.
  </Step>
  <Step title="Save">
    Create the target and confirm that its first status observation matches your platform.
  </Step>
</Steps>
