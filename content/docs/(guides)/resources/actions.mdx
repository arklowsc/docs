An action describes a kind of work your platform performs. A run is one accepted unit of that work.

For example, `orders.created` can be an action. The order placed by one customer is a run of that action. The action supplies the contract and flow; the run carries the payload, tags, current state, and delivery history.

## Variant

The variant is the action's canonical name. Use dot notation to describe the domain and event or operation:

```text
orders.created
inference.requested
calls.process
```

The variant is used by [HTTP ingress](/resources/sources/arklow/ingress), queue sources, rules, and SDK listeners. Treat it as a stable contract with callers.

## Lifecycle

A run moves through a small set of public states.

| State | Meaning |
|---|---|
| `queued` | Arklow accepted the run and it is ready to be evaluated |
| `dispatch_wait` | The selected lane cannot admit the run yet |
| `scheduled` | The run is waiting until a requested time |
| `retrying` | A prior attempt ended and the next attempt is waiting to begin |
| `running` | Arklow admitted the run and is delivering it |
| `ack_wait` | The destination has the run and final settlement is outstanding |
| `succeeded` | The run settled successfully |
| `failed` | The run reached a permanent failure or exhausted its lifetime |
| `canceled` | The run was canceled before successful completion |

[Delivery guarantees](/fundamentals/delivery-guarantees) defines attempts, settlement, and redelivery for these states.

## Create an action

<Steps>
  <Step title="Name the work">
    Create an action in the dashboard and enter a stable variant such as `orders.created`.
  </Step>
  <Step title="Link a destination">
    Open the action's **Flow** and link the destination that should receive the work. Set the fallback destination as default when the flow has more than one.
  </Step>
  <Step title="Add routing where needed">
    Add rules when payloads or tags should choose a different destination or control lane.
  </Step>
</Steps>
