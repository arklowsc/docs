## Integration paths

| Path | Use it when 
|---|---|
| **[Listener Delivery](#listener-delivery)** | You want your code to receive work from Arklow directly.
| **[External Work](#external-work)** | An existing pipeline starts and executes the work.

## Authentication

Listener delivery and external registration authenticate with an Arklow organization API key.

## Listener Delivery

### Setup

See the [Quickstart](/quickstart).

### Listener options

| Option | Behavior |
|---|---|
| `namespace` | Claims work from every active SDK destination in the organization with the same namespace |
| `maxOutstanding` | (Optional) Sets the maximum number of unsettled deliveries this listener can hold; defaults to `1024` |
| `variants` | Limits claims to the named action variants; an omitted or empty list accepts every variant |
| `transport` | Uses `grpc` by default; use `poll` to claim over HTTPS |

### Start the listener

Call `listen(options, handler)` on the listener client.

```typescript
// Other SDK languages follow the same form.
const running = listener.listen(
  {
    namespace: "billing",
    variants: ["invoice.process"]
  },
  async (delivery) => {
    await processInvoice(delivery.payload);
  },
);
```

### Delivery fields

| Field | Value |
|---|---|
| `actionRecordId` | Stable run identifier across attempts |
| `attempt` | Delivery attempt number |
| `variant` | Action variant |
| `payload` | Run payload |
| `tags` | Tags attached to the run, when present |
| `leaseRemainingMs` | Milliseconds left on the current lease |
| `timeoutRemainingMs` | Milliseconds left before the run timeout, when one applies |

## Settlement

| Method | Effect |
|---|---|
| `await delivery.ack()` | Marks the run as succeeded |
| `await delivery.nack()` | Rejects the attempt and allows redelivery |
| `await delivery.nack({ retryAfterSeconds })` | Schedules the next attempt after the supplied number of seconds, a positive integer |
| `await delivery.nack({ retry: false })` | Marks the failure as permanent |
| `await delivery.defer()` | Stops redelivery and releases the listener slot while another process completes the work. See [Pattern B](/fundamentals/acknowledgement-and-deferral#pattern-b-work-is-performed-asynchronously). |
| `await delivery.extend(ms)` | Extends the current lease within the run timeout |

A handler that returns acks the delivery, and a handler that throws nacks it. The first explicit acknowledgement or rejection takes precedence over the handler result.

After `defer()`, the handler result has no effect. Any `nack()` call other than `nack({ retry: false })` throws an error.

Until you settle or defer a delivery, the listener renews its lease up to the run timeout. Call `extend()` to move the deadline by a known amount.

Use `actionRecordId` as the idempotency key across attempts. [Delivery guarantees](/fundamentals/delivery-guarantees) talks about delivery behavior that can be important.

### Shutdown

Call `await running.stop()` during shutdown. The listener stops claiming work and waits for its current handlers and settlements to finish. A handler that never settles also prevents `stop()` from completing.

## External Work

Call `registerExternalWork` after an existing pipeline starts work that Arklow should track. Registration creates a run.

```typescript
// Other SDK languages follow the same form.
const work = listener.registerExternalWork("invoice.process", {
  externalRef: invoiceJob.id,
  tags: { customer_id: invoiceJob.customerId },
  payload: invoiceJob.payload,
  timeout: 900,
});

const actionRecordId = await work.recordId;
```

| Option | Behavior |
|---|---|
| `variant` | Selects the action for the run |
| `externalRef` | Uses an existing job identifier as an idempotency key |
| `tags` | Attaches work identity and routing context |
| `destinationId` | (Optional) Associates the run with a destination linked to the action |
| `payload` | Stores the run payload |
| `timeout` | Sets the maximum lifetime in seconds; defaults to `3600` and accepts `1` through `86400` |

When `destinationId` is omitted, the action's normal rule and default-destination selection apply. Reusing an `externalRef` returns the existing run. Supply a stable reference when registration may be retried; otherwise the client generates one.

### External work handle

| Member | Behavior |
|---|---|
| `externalRef` | The reference of this work, including one that the client generated |
| `recordId` | Resolves to the Arklow run identifier |
| `update()` | Extends the activity lease while the external work remains active |
| `complete()` | Marks the run as succeeded |
| `toJSON()` | Serializes the identifiers needed to resume tracking in another process |

Registration starts a 60-second activity lease. Call `update()` on a cadence shorter than 60 seconds while the work remains active. The client coalesces calls made before another extension is needed, and the lease cannot move beyond the run timeout.

Await `recordId` before calling `toJSON()`. Restore the serialized handle after a process handoff or restart with `externalWorkHandle()`.

<Warning>
  External work has no rejection or retry settlement. When a lease expires, it also marks the run as complete.
</Warning>
